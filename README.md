# TetherMax 메인 페이지 개선 · 개발 확인용 프로토타입

Figma 기획서(Mainpage improvement · KO)와 PRD(개요 · FE · BE 요구사항) 기준으로 화면 케이스를 하나씩 열어 확인하는 프로토타입입니다.

## 화면 구성

| 영역 | 내용 |
| --- | --- |
| 상단 막대 | 버전 배지, KO / EN 전환, 변경 사항 번호 표시, [변경 사항] 패널 |
| 화면 · 시나리오 설정 | 화면 묶음 · 케이스, 회원 상태값, 사용자 폭(창 폭 · 1440 · 390), 처음부터 |
| 화면 | 실제 크기(100%). 사용자 폭 [창 폭]에서 브라우저 창을 늘이고 줄이면 구간별 화면이 바뀝니다 |
| 변경 사항 패널 | 케이스별 변경 사항. 번호는 화면 위 분홍 번호와 같습니다 |

주소 끝에 케이스 ID를 붙이면 그 케이스로 바로 열립니다. 예: `/#MP-W03-d`, 상태값이 있는 케이스는 `/#MP-W01@3`

## 폴더

| 경로 | 내용 |
| --- | --- |
| `src/proto.html` | 화면 본체. 데이터 플래그 · 번호 표시 · 입금 알림 플로우 시뮬레이션(브리지) 포함 |
| `src/index.html` | 상단 막대 · 설정 · 변경 사항 패널 |
| `src/cases.js` | 케이스 정의. 화면 묶음, 케이스 ID, 상태값, 변경 사항 문구, 번호를 붙일 요소(셀렉터) |
| `public/` | 그대로 복사되는 파일 (글꼴) |
| `assets/` | 거래소 로고 · 잔액 카드 이미지 (없으면 로고는 이니셜 원으로 표시) |
| `scripts/build.mjs` | `dist/` 생성 (Tailwind CSS 생성 · 케이스 주입 · 파일 복사) |
| `tests/run.mjs` | 전 케이스 자동 점검 |

## 작업 순서

```bash
npm install
npx playwright install chromium   # 처음 한 번 (점검용 브라우저)
npm run check                      # 빌드 + 전 케이스 점검
```

- 케이스 · 변경 사항 문구 수정: `src/cases.js`
- 화면 수정: `src/proto.html` (Tailwind 클래스 그대로 사용, 빌드 시 CSS 생성)
- 점검 결과가 `전체 N건 통과`일 때만 push 합니다

## 배포 (Vercel)

- 설정: `vercel.json` (Build `npm run build`, Output `dist`)
- 브랜치에 push → 미리보기 URL 생성 → 확인 후 `main`에 합치면 공유 URL 갱신
- 공개 범위: 링크가 있으면 누구나 볼 수 있음

## 케이스 데이터 플래그

실제 데이터에 없는 경우를 보려고 케이스가 주소로 넘기는 값입니다. 화면에 "테스트 데이터"로 표시됩니다.

| 플래그 | 내용 |
| --- | --- |
| `noBad` | 확인 필요 UID 0개 |
| `singleBad` | Bybit(UID 1개)를 이용 제한으로 |
| `dexMulti` | Lighter 지갑 2개 |
| `cexOnly` · `dexOnly` | CEX만 · DEX만 연동 |

## 범위 밖 (현행 그대로)

- 연동 완료 · 연동 실패 화면
- 확인 필요 UID의 사유별 처리 안내 (프로토타입은 토스트로 대체)
- 출금 확인 · 신청 완료 (현행 컴포넌트, 프로토타입은 흐름 확인용 대체 화면)
